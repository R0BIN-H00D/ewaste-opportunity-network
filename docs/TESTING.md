## Backend test setup
- Tests use an **in-memory MongoDB** (`mongodb-memory-server`). It downloads a `mongod` binary the first time (needs internet once).
- Alternative: point at a local MongoDB with `TEST_MONGODB_URI=mongodb://127.0.0.1:27017/ewaste_test npm test` (the DB name **must contain "test"** — the suite wipes it).
- `tests/health.test.js` needs no database.
- `tests/geo.test.js` — privacy fuzzing never returns the exact point (regression for a bug found on first run).
- `tests/models.test.js` — registry (36 models), hidden password hash, unique/idempotency rules, BR-04/06/07 constraints, insert-only audit log, soft delete.
- `tests/devices.test.js` — auth/roles, validation (422), mass-assignment, magic-byte upload check, public vs owner serialisation, filters/search/pagination/geo, NoSQL-operator rejection, ownership (403), lock rule (409), soft delete, reports, 501 stubs, suspended account, token revocation.
